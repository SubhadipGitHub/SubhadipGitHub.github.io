Cross-cloud, event-driven integration hub

AP and PO data had to reach third-party platforms outside Oracle reliably, in near real time, and with a full audit trail.

  • 40integrations
  • 50,000records a day
  • 3h → 30mend-to-end latency
  • −60%errors

What I built

  • Fusion ERP business events feed OIC3 orchestrations.
  • Metadata-driven routing: rules live in ATP and are maintained through an APEX admin UI rather than hardcoded.
  • Outbound REST connects to the external platforms.
  • A central audit and error store in ATP, with an APEX operations dashboard.
  • Documents are transformed from base64 to PDF in-flow.

Key decisions

  • Event-driven over scheduled batch to cut latency.
  • Routing as data, not code, so new targets ship without redeploying integrations.
  • Governance on ATP and APEX to keep operational control inside OCI.

02
  • Deloitte internal initiative
  • Fusion AI Agent Studio · Microsoft Graph

Agentic AI on Fusion, bridged to Microsoft 365

A known class of Fusion failure always needed the same fix, yet it still meant a ServiceNow ticket and people chasing each other to apply it and close the issue.

  • 8resolution steps automated
  • 2clouds: Oracle and Microsoft 365
  • Humanapproval before every commit

What I built

  • An Oracle Fusion AI Agent Studio agent identifies the resolution step and calls external REST tools against Fusion and other APIs.
  • A human-approval node sends email through Microsoft Graph, authenticated with M365 / Entra ID.
  • Scheduled async workflows resume once the approver responds, and write the result back to Fusion.

Key decisions

  • Humans stay in the loop for anything that commits a transaction.
  • Async by design, so long-running approvals never hold sessions open.

Role Architect, team of 3

Architecture governance at run-time

On a live Fusion estate, ownership across support tiers was unclear and every Oracle quarterly update carried risk.

  • 400 → 150backlog
  • 3d → 1dFusion post-clone release cycle

What I built

  • An operating model with L1.5 / L2 / L3 tiering and a RACI.
  • Environment-aware release planning around P2T refreshes, quarterly updates and close freezes.
  • Regression and evidence tooling for quarterly update certification.

Key decisions

  • Sequence changes around Oracle’s quarterly cadence, not against it.
  • Tier ownership so L3 architects aren’t pulled into L1 noise.
